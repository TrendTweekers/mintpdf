Try it now

Copy, paste, done. The anonymous tier needs no key at all.

terminal
curl -X POST https://pdfmint-production-0b25.up.railway.app/v1/pdf \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# Hello\n\n| item | price |\n|---|---|\n| Widget | $9 |","footerText":"Generated with PDFMint","pageNumbers":true}' \
  --output hello.pdf

Need more than 5/day? Free key, no card: curl -X POST …/v1/keys -d '{"email":"you@example.com"}' → send it as Authorization: Bearer pm_…

Use it from Claude

Add one block to your MCP config, then ask for a PDF in plain language. The agent writes the Markdown, calls the tool, and hands you a download link.

claude_desktop_config.json
{
  "mcpServers": {
    "pdfmint": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://pdfmint-production-0b25.up.railway.app/mcp"]
    }
  }
}

API

Three endpoints. That's the whole surface.

EndpointWhat it does
POST /v1/pdfBody: one of html, markdown, url, plus options (format, landscape, margin, headerText, footerText, pageNumbers). Returns PDF bytes, or a JSON download link with "output":"url".
POST /v1/keysFree API key by email. No card, no verification loop.
POST /mcpMCP endpoint (streamable HTTP), same capabilities as the REST API.
Why not just self-host Gotenberg? You can, and if you want to run and patch your own Chromium fleet, you should; it's excellent and free. PDFMint is for the other case: you or your agent need a PDF now, without deploying anything, and you want Markdown to come out looking good by default. We run the browsers, you send content.
